---
title: Usage
description: Encode and decode single- and multi-part UR strings.
---

```ts
import { encode, decode, decodeMessage, Encoder, Decoder, UrType } from "@qntx/ur";

const data = new TextEncoder().encode("hello");
const ur = encode(data, UrType.bytes());
const { payload } = decode(ur);
const fromMessage = decodeMessage(ur);

const message = new Uint8Array(200).fill(7);
const encoder = Encoder.bytes(message, 30);
const decoder = new Decoder();
while (!decoder.complete) {
  decoder.receive(encoder.nextPart());
}
const recovered = decoder.message();
```

`encode` / `decode` are single-part. `decodeMessage` returns the payload or throws `NotSinglePart` on a fountain URI. `Encoder.nextPart` emits a single-part UR when `fragmentCount === 1`, otherwise fountain `ur:<type>/<seq>-{K}/<body>`. `Decoder.receive` accepts both. Duplicate single-part URIs of the same type are ignored: the body is not compared; the first payload wins. Mixing single-part and fountain in one session is `InconsistentPart`. `UrType.bytes()` is the `bytes` UR type.

Recovered bytes are untrusted. dCBOR and type checks are the caller's job; L3 does not parse application payloads.
